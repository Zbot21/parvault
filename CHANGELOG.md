# Changelog

All notable architectural decisions, security hardenings, and user-facing features for `parvault` (`parvault`, `parvault-seed`, `parvault-gateway`, `parvault-fuse`, and `parvault-bench`) are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Security
- **Plugin tokens off the command line (F-51).** `parvault-fuse`, `parvault-sync` and `parvault-status` take `--macaroon-file <path>`, refused if group or others can read it. `--macaroon <token>` still works but is visible to every local user in `/proc/<pid>/cmdline`; `--help` and the docs say so, and the examples use the file.
- **`parvault token inspect` redacts the tag.** The HMAC tag is the bearer secret, so it now prints as `<redacted>` (text and JSON) unless `--show-tag` is given, as with the macaroon `Debug` output (F-43, L-44 item 8).
- **The status page needs a read-only token and an IP-literal Host (F-46 fixed, item 3).** `parvault up --status-http` / `daemon start --status-http` now refuse a request without a valid, read-only, unscoped token (only in the `Authorization` header: `Bearer`, or the token as the Basic password; a `?token=` in the URL is ignored; fixed 401; L-52) and a DNS-name `Host` (403). The server moved from tokio to a blocking `std` listener on the HTTP edge it now shares with WebDAV (32 connections, 8 per IP, 8 KiB heads, 5 s deadline), behind the new `status-ui` feature. With `--status-http` set the daemon creates the gateway macaroon root key if there is none. **Breaking:** scripts that read `/api/v1/health` without a token get 401.
- **Status over the gateway socket needs a read-only token (item 3, F-46).** New `IpcCommand::QueryStatus { macaroon }` / `IpcResponse::StatusSnapshot` (appended). `status_auth_decision` refuses it without a gateway root key or a published snapshot, without a valid, unexpired `ReadOnly` token, with a file-scoped (`AllowedManifest`/`ByteRange`) token, or with an `AllowedPeerUid` that does not match the socket peer. **Breaking:** the status snapshot (`router_nas::RouterNasLiveSnapshot`, now an alias of `gateway::ipc::StatusSnapshot`) drops `pairing_sas_code` and `watched_folder`, `stripe_size_bytes` becomes `u64`, strings are capped at 256 bytes and peers at 128; the status page and `/api/v1/health` JSON no longer show the SAS code or the watched folder.
- **Whole-file gateway reads need a token (F-47).** `IpcCommand::FetchPayload` carries a macaroon checked against the whole file like `FetchRange` (manifest scope, range, expiry, peer UID); with a gateway root key set, a missing or out-of-scope token is refused. **Breaking (gateway protocol and library):** the `macaroon` field is appended to `FetchPayload`; `GatewayIpcClient::fetch_into_memfd`, `fetch_payload_to_fd` and `GatewayBus::fetch_into_memfd_sync` take a `macaroon` argument; new `fetch_payload_bytes(_sync)`.
- **Ticket PoW is bounded on both sides (QA 2c D1, R2).** A client refuses a peer's ticket PoW demand above its own level + 4 bits (cap 20, `reject.ticket_pow_demand_excessive`) instead of minting forever, and a seed's admin RPC refuses `min_public_pow_bits` above 16 (`reject.required_pow_bits_excessive`), so an operator cannot lock out every new public client.
- **Public status is coarse (F-44).** `QueryNodeStatus` reports free space rounded down to whole MiB, used space in power-of-two GiB buckets and SLA to one decimal, not exact values.
- **Gateway identity statements are pinned (F-17).** `GatewayIdentityStatement::verify(now)` is replaced by `verify_pinned(expected_authority, now)`, which refuses another authority and a lifetime outside `(0, 30 days]`. **Breaking (library):** callers (the suite broker) must pin their authority.
- **Post-quantum DHT manifests fail closed (PQ-DHT).** The DHT reader refuses `PostQuantumManifest` candidates (`reject.dht_owner_unbindable`) until an owner PQ key is bound to an identity.
- **Reason codes on the remaining checks (2c D-ADR).** Oversized wire frames (`reject.wire_frame_oversized`), LAN beacons (`reject.beacon_*`), per-peer quotas (`reject.peer_quota_exceeded`, `reject.peer_write_amplification`), hybrid signatures (`reject.hybrid_sig_*`), PoR pre-screens (`reject.por_*`) and abuse reports (`reject.abuse_report_*`) now log a distinct code; each has a claim in `.enforcement.map`.
- **WebDAV requires a token (F-43, L-43, L-44).** Every request to the built-in WebDAV server (`parvault up --vfs-webdav-listen`) and to `parvault-fuse webdav` needs a read-only macaroon (`parvault token mint --read-only`), sent as `Authorization: Bearer <token>` or as the Basic-auth password with any user name; a token without `ReadOnly` is refused (403). Missing, malformed, forged or expired tokens get an identical 401, and a file-scoped token gets 403 (never 404) for any other path or a listing. `parvault-fuse webdav` now requires `--macaroon` and accepts only that token or an offline attenuation of it. Request heads have a 5 s deadline and an 8 KiB cap, and connections are capped at 64 overall and 8 per source IP. There is no TLS yet (planned for `v0.6.0`): over a LAN the token travels in clear. Windows' WebDAV client sends Basic over plain HTTP only after `BasicAuthLevel` is set to 2 (see QUICKSTART Recipe F).
- **The seed no longer blocks on syndication (B-SEED-SYND, L-46).** `parvault-seed` uploads a lite stripe to its mesh peers as a job off its event loop and outside its lock (4 parallel puts, a 20 s deadline after which it answers in about 20 s plus one in-flight put, ≈24 s worst case, under the 30 s client timeout; a peer that fails once gets no further puts in that job), so other clients, audits and the admin RPC are answered while it runs. A seed runs at most 2 such jobs, 1 per sender; a further sender is refused with `reject.syndication_busy`, and `watch-folder` retries that stripe after 2, 5 and 10 s before leaving it for the next pass.
- **Legacy blinded leases are unreadable (F-42, D-2).** A blinded shard whose lease has no registered capability key (stored before keys were registered) is no longer served to anyone; it expires by lease.
- **Signed blinded deletes (F-41, L-42).** A blinded shard is deleted only by `DeleteBlindedShardSigned`, signed by the shard's capability key over the host's key, the locator, the content hash and a timestamp (30 s window); the old MAC tombstone, which anyone who had seen the delete verifier could forge, is always refused. A delete names the stored shard only (a valid delete for X can no longer remove Y), and a locator's capability cannot be replaced by a re-put while its lease exists. Blinded shards stored without a registered capability cannot be deleted and expire by lease. **Breaking:** wire variant `DeleteBlindedShardSigned` appended (23 request variants); `DeleteBlindedShardTombstone` refused; removed `BlockStore::delete_blinded_shard_with_tombstone`, `BlindedShardLeaseManager::execute_tombstone`, `ZeroTrustSeedServer::execute_blinded_tombstone`, `MeshClient::delete_blinded_shard_tombstone` and the `WireRolePolicy::tombstone_via_seed_server` hook; added `BlindedShardCapability::sign_delete` / `verify_delete`, `BlockStore::delete_blinded_shard_signed`, `MeshClient::delete_blinded_shard_signed`, `BlindedShardLeaseManager::remove_lease`.
- **Blinded reads expire (F-40).** A `GetBlindedShard` read token must be signed within 30 s of the host's clock; a captured token no longer stays valid. PoR audits and blinded reads log reason codes (`reject.por_*`, `reject.blinded_read_*`). **Breaking (library):** `BlockStore::get_blinded_shard_authorized` takes `now_ms`.
- **Bounded, epoch-bound eviction orders (F-09).** Orders carry a signed `council_epoch` (signing domain `parvault-bad-actor-eviction-order-v2:`) and are admitted only for the installed council epoch, issued within the last 7 days (5 min clock skew), with an expiry at most 365 days after issue; permanent orders (`expires_at_ms = 0`) are refused. Replay ids are kept until their order expires and a full cache refuses instead of evicting. An order from a newer council epoch is refused and the node fetches the newer manifest from its admitted peers (`GetCouncilManifest`, bounded). Takedown, emergency and `evict --propagate` orders expire after 90 days; `evict --propagate` needs the node to be a council member and, until parvault-control adds cosigning, a council quorum of 1 (with a larger quorum it refuses instead of broadcasting an order every peer would refuse). **Breaking:** `-v1:` orders no longer verify; `SignedBadActorEvictionOrder` gains `council_epoch` (bincode orders without it do not decode; struct literals fail to compile: use `SignedBadActorEvictionOrder::unsigned` + `with_signature`); `issue` takes `council_epoch`; `apply_signed_eviction_order_with_quorum` takes the council manifest instead of `(keys, quorum)`; `encode_signing_payload_stack` takes `council_epoch`; the wire enums gain `GetCouncilManifest` / `CouncilManifestResult`. `parvault-control` (item 6) must sign `-v2:` orders with the epoch.
- **Signed eviction council (F-08).** The council that signs eviction orders is a signed, epoch-versioned manifest: `parvault council init --member <HEX> ... --quorum <N>` signs epoch 1 with the ring genesis, `parvault council install --manifest <HEX>` installs one; no shipped tool yet signs a public-mode epoch 1 (tracker admin key) or any later epoch (quorum of the previous one): that comes with `parvault-control`, item 6, `parvault council show` prints it. The quorum must be a strict majority. A node with no manifest accepts no council orders; an order signed by the node's own key still applies on that node only. **Breaking:** `PARVAULT_EVICTION_AUTHORITIES`, `PARVAULT_TRACKER_EVICTION_QUORUM`, the config keys `eviction_authorities` / `tracker_eviction_quorum` (now ignored), and `parvault-seed start --council-pubkeys` / `--council-quorum` are removed, and the seed admin RPC no longer authorises keys from `PARVAULT_EVICTION_AUTHORITIES`. Operators (and `parvault-control`, item 6) install a manifest instead.
- **Syndication grants are bound to the sender (F-38, L-40).** A seed refuses a `SyndicateLiteStripe` whose repair grant is not owned by the authenticated sender (`reject.syndication_grant_not_sender`); with the device-cert check this binds the grant to the owner. The lite client sends as its vault identity again; `parvault identity --seed-phrase/--vault-namespace` prints the Vault Device Peer ID to certify.
- **Voucher expiry (F-35).** Blinded-shard vouchers carry a signed expiry (default 30 days, at most 90); a spent nullifier is kept until its voucher expires, and a full ledger refuses new vouchers instead of evicting old nullifiers, so a spent voucher can never be replayed. Older vouchers no longer verify.
- **Voucher issuer policy (F-24).** A blinded-shard voucher is honoured only if its issuer is a ring member the node knows (or a seed's configured issuer); the node no longer trusts whichever issuer a voucher names. Ephemeral per-shard issuers are refused until v0.6.0.
- **Rendezvous quotas (F-22).** `RegisterWanRendezvous` stays open before admission, but a signer may hold at most 8 slots and a subnet 32 live entries; only admitted signers are recorded in the admission-IP map.
- **Onion relays need admission (F-33, L-38).** `RelayPqOnionEnvelope` is admitted like other storage requests: the originator presents its ring credential at the entry relay, and each relay at the next hop. A relay keeps at most 4 forwards in flight per sender and 64 in total, and refuses more (`relay busy; retry later`). Forwards no longer block the swarm task (F-18).
- **F-37 (critical, pre-release):** a public-commons node outside any ring used the all-zero key as a placeholder genesis, and signatures were checked non-strictly, so a stranger could forge a one-hop chain and be admitted as a ring member. A node with no ring now has no genesis and refuses every `HandshakeWoT`; all Ed25519 checks use strict verification.
- **Ring admission is enforced (item 2b, `docs/security/TRUST_FINDINGS.md`).** Storage requests (`PutShard`, `SyndicateLiteStripe`, `PutDhtEnvelope`, `PutBlindedShard`, onion final delivery) need an admitted sender; others get `peer not admitted; v0.5.0 requires ring admission`. Start a ring with `parvault wot init` and add devices with `parvault wot invite` / `parvault wot install-chain`. No node creates a genesis on its own any more: a private-mode daemon outside any ring, or with conflicting genesis sources, refuses to start. `v0.4.0` peers are refused.
- Onion originators (`OnionOriginator`) never present a ring credential to the entry relay; only the relay's forward to the final target is admitted.
- Public-commons tickets are bound to the verifier and fresh for 10 minutes, rate-limited per subnet, and never evict a live admission; admissions are written in batches.
- The handshake returns one fixed refusal text; members may sub-invite at most 64 keys; inbound Kademlia records need an admitted source; repair grants are keyed by owner and bound to the shards stored with them; only a shard's owner can delete it.
- `HandshakeWoT` admits only the sender's own chain; the accounted shard owner is always the sender (foreign owner claims are refused); a syndication device cert must name the sender.
- Repair grants register only after a stored shard, for its stripe, without replacing another owner's grant; witness repair reads need the registered grant.
- The DHT reader ignores envelopes not sealed by the reading identity; inbound Kademlia records must be valid signed envelopes.
- Slashing gossip is no longer applied (until proof-carrying evidence, 2c); the genesis and the node's own key are never slashed.
- `--no-lan-discovery` turns mDNS off; mDNS never feeds Kademlia, admission does.

### Added
- **`parvault-status` sidecar (item 3).** The status page as its own binary, built with `--no-default-features --features status-ui` (no tokio, no libp2p). It holds no key, pins one read-only `--macaroon`, reads the snapshot with `QueryStatus` over the gateway socket, and has no default `--listen`. Against a pre-v0.5.0 daemon it exits with a message saying so. Shipped in releases for both musl targets.
- File manifests are version 2: each stripe records a chunk Merkle root per shard (`shard_chunk_roots`, `por::chunk_merkle`, `4 KiB` chunks) for storage audits. Version-1 manifests and folder snapshots still decode, with no roots (unauditable). The audit loop does not issue challenges yet.
- `MeshWireRequest::AdmitPublicTicket` / `MeshWireResponse::AdmitPublicTicketAck` (appended; existing indices unchanged) and `parvault wot init` / `invite` / `install-chain`.

### Removed
- `CorrelatedOutageController::verify_weather_quorum` and `SignedWeatherAttestation` (never called; F-15).

### Changed
- **Feature split: plugins link no async runtime (item 3, L-48).** New Cargo features `ipc-client`, `status-ui` and `daemon-runtime` (`default = [daemon-runtime, vfs, status-ui]`); `parvault-fuse`, `parvault-sync` and `parvault-status` build with `--no-default-features` and link no tokio, libp2p, mio or quinn (checked in CI). Stripped `--profile soc` aarch64 musl: `parvault-fuse` 3,084,816 → 1,185,456 B, `parvault-sync` 3,084,840 → 725,264 B, new `parvault-status` 1,054,352 B. **Breaking (library):** `--no-default-features` builds of `parvault`/`parvault-seed` need `--features daemon-runtime`; runtime modules (`network`, `bootstrap`, `config`, `storage::{block_store, quota, eviction, council}`, `gateway::{engine, server, cli_runner}`, `por::verifier`) exist only with it; `GatewayBus::InProcess` and the async client methods need it.
- **CodeQL advanced setup (L-50).** New `.github/workflows/codeql.yml` (Rust and GitHub Actions; push and pull request to `main` and `v0.5.0/**`, plus weekly) with `.github/codeql/codeql-config.yml`, which ignores only six test suites that hold literal keys and tokens on purpose. **The owner must switch the repository from CodeQL default setup to advanced setup in GitHub settings** for it to take effect. `ci.yml` now runs with `permissions: contents: read` (alerts #1, #3, #41).
- **Breaking: plugin self-tests are client-only (item 3).** `parvault-fuse self-test` and `parvault-sync self-test` no longer host an in-process gateway; they run against the daemon on `--socket` and present `--macaroon`. `scripts/plugin_self_test.sh` starts a standalone gateway, mints a token and runs both (CI and release use it); `tests/plugin_self_test.rs` covers the in-process case.
- Stripes that no ring peer accepted (or stored with no peers) are no longer reported as a finished backup. `watch-folder --once`, `file store` and `parvault-sync push` print `N stripe(s) kept only on this machine: NOT backed up` and exit with code `3` unless given `--allow-local-only`; `up --folder`, `--vfs-seed-dir` and the `watch-folder` loop log it as an error each pass; `parvault status` shows `Local-Only Stripes`. **Protocol change:** gateway IPC appends `IpcResponse::StoreSuccessLocalOnly` (discriminant 4); a plugin built against the old enum fails to decode it rather than reporting success (parvault-suite re-pins in item 7). Async `GatewayBus` callers get the count from `store_payload_fd_counted`. When some shards reach peers, they stay there and only the rest are stored locally; `parvault status` counts only listed stripes that still have local shards. A listed stripe is dropped once k or more of its shards are on peers (at placement) or after a successful lite-seed re-syndication; that re-syndication re-sends the whole stripe, so copies already on peers are left unreferenced (README Known Limits).
- `list-snapshot` prints each file's full stripe roots, the value `evict --merkle-root` takes.
- The gateway engine's 40 mesh lanes send as the owner identity (one `PeerId`).
- The seed's syndication puts carry an empty owner claim (accounted to the seed).
- **Shared wire handler (`#codehealth`):** the daemon and `parvault-seed` now serve every `MeshWireRequest` through one `handle_mesh_wire_request` in `src/network/wire_handler.rs`; the nine role differences are explicit `WireRolePolicy` hooks. Behaviour and wire format are unchanged (pinned by `tests/wire_handler_equivalence.rs`).
- **Log targets:** the seed's wire-handler warnings now log under `parvault::network::wire_handler` instead of `parvault_seed`, and the daemon's mDNS discovery line under `parvault::network::server_events`. The default filters (`parvault=info`) still print them; a custom `RUST_LOG` that names `parvault_seed` will not.
- `parvault` command implementations moved from `src/main.rs` into `src/cli/`; `PlacementEngine` and `TokenBucketRateLimiter` moved to `network::placement` / `network::rate_limit` (re-exported at their old paths).
- Crate version `0.5.0`; `deploy/Dockerfile.musl` builds `--profile soc` like the release workflow.

### Added

  - Expanded formal verification to **`15/15` Kani symbolic harnesses** (adding `proof_pinned_ring_capacity_invariant`, `proof_fuse_header_parser_no_panic`, `proof_gateway_ipc_frame_header_bounds`, `proof_vfs_block_window_power_of_two_and_zero_bounds`, `proof_macaroon_caveat_attenuation_monotonic_and_zero_key_rejected`) + **`7/7` TLA+ TLC specifications** (`ParVaultZeroKeyAdminAndQuorum.tla`) and **`122/122` release tests**.

## [`0.3.0`] - 2026-11-11

### Added
- **Zero-IP Home LAN Auto-Discovery, Persistent Peer Registry & 4-Word SAS Pairing (`ADR-18`, `src/network/discovery.rs`):**
  - Added cryptographically signed `LanBeaconPacket` broadcasting on UDP port `4009` (multicast group `239.255.80.86`, broadcast `255.255.255.255`, and ephemeral localhost fallback) signed under domain `"parvault-lan-beacon-v1:"`.
  - Enforced strict cryptographic binding between `ed25519_pubkey` and `libp2p_peer_id` so rogue clients on Wi-Fi cannot spoof peer identities.
  - Implemented 4-word BIP-39 SAS pairing code derivation (`derive_4word_pairing_sas`, `verify_lan_pairing_code`) allowing devices to mutually authenticate and pair with zero IP configuration.
  - Added DHCP-resilient persistent peer store `KnownPeersStore` (`known_peers.json`) updating socket addresses dynamically when home routers renegotiate DHCP leases without invalidating pinned `PeerId`s.
  - Added automatic zero-IP fallback across all high-level CLI commands (`watch-folder`, `restore-folder`, `file store`, `file restore`, `leave`, `status`) via `resolve_zero_config_peers`.
- **Tiny-SoC 1 MiB Streaming Stripe Profile, Allocation Diet & Turnkey Router Packaging (`ADR-18`, `src/storage/block_store.rs`, `Cargo.toml`, `deploy/`):**
  - Introduced configurable streaming stripe sizes in `BlockStore` (`BlockStore::with_stripe_size_bytes`) and `HardwareProfile` (`RouterSoc` `1 MiB`, `HomelabNas` `4 MiB`, `Desktop` `16 MiB`).
  - Reduced transient peak working set memory (`VmHWM`) during Reed-Solomon $GF(2^8)$ encoding/reconstruction from `57.30 MiB` down to **`9.39 MiB`** (6.1x reduction), enabling safe execution within a strict 32–48 MiB cgroup.
  - Authored `deploy/Dockerfile.router-soc` (`FROM scratch` container image), OpenWrt `/etc/init.d/parvault-nas` `procd` service script, and updated `deploy/prplos-lxc-manifest.json` for prplOS gateway integration.
  - Authored comprehensive integration manual [`docs/ROUTER_SOC_HARDWARE_GUIDE.md`](docs/ROUTER_SOC_HARDWARE_GUIDE.md).
- **Embedded Zero-Dependency Router Cloud-NAS Status HTTP Server (`ADR-18`, `src/router_nas.rs`):**
  - Implemented lightweight HTTP server using `tokio::net::TcpListener` serving `GET /api/v1/health` (live `VmRSS`/`VmHWM`, uptime, quotas, pairing code), `GET /api/v1/peers` (LAN peers), and `GET /` (embedded HTML5 dashboard `< 6 KiB`).
  - Added turnkey single-command appliance mode `parvault up` combining P2P storage daemon, UDP discovery responder, embedded web status server, and background folder synchronization.
- **Zero-IP Online WAN Rendezvous, STUN-over-Noise Reflection & Dynamic-IP Presence (`ADR-18`, `src/network/wan_rendezvous.rs`, `src/network/behaviour.rs`):**
  - Added `RegisterWanRendezvous` and `LookupWanRendezvous` wire RPCs to `MeshWireRequest` / `MeshWireResponse`.
  - Implemented blinded WAN rendezvous mailbox deriving `slot_key = HKDF(code, "slot-v1")` and AEAD wrapping key `wrap_key = HKDF(code, "wrap-v1")` for zero-knowledge 4-word pairing across cities.
  - Implemented STUN-over-Noise external address reflection extracting observed socket addresses from authenticated `libp2p` Noise XX connection metadata.
  - Added zero-knowledge dynamic-IP presence publishing encrypted endpoint heartbeats to blinded DDNS slots, surviving residential ISP address rotations.
- **Open Public Commons / BitTorrent-Style Public Swarm Mode (`ADR-18`, `src/network/wot.rs`, `src/network/wan_rendezvous.rs`):**
  - Added `TrustPoolMode` (`PrivateRing`, `PublicCommons`, `Hybrid`) in `WebOfTrustRegistry`.
  - Added self-signed Hashcash Proof-of-Work admission ticket `PublicCommonsTicket` (`DEFAULT_PUBLIC_WOT_POW_BITS = 12`) allowing stranger nodes to join public swarms without invitations.
